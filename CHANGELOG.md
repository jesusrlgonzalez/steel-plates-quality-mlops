# Changelog

All notable changes to this project are documented here. Versions follow
[Semantic Versioning](https://semver.org/). The frozen model, its metrics and
the consumed holdout have not changed since v1.0.0.

## [Unreleased]

## [1.7.0] - 2026-11-17

### Added
- Power BI page «SEGUIMIENTO DE REVISIÓN HUMANA» (`review_tracking`) for P02, authorised by the OWNER on 2026-11-17: table `Seguimiento_Revision` (612 rows, 13 measures from `revision_humana.dax`), expression `RutaRevisionCSV` derived from `RutaCSV`, 15 visuals. Built by `tools/prepare_review_powerbi.py`, opened, refreshed, reconciled and saved in Power BI Desktop; checked by `tests/test_review_powerbi.py`. Evidence in `docs/production/POWERBI_P02_REVIEW_PAGE.md`. Closes P02 reservation R3. Synthetic data, level A.

### Changed
- The certified PBIX is the Desktop save with the new page: SHA256 `a48291e5…435f4` (274,350 bytes). Previous pages, `ML_Holdout` (389 rows), the 34 earlier measures and the 3 relationships are unchanged; no auto date tables. `a37f3743…` is superseded.
- `fecha_corte` in the P02 export is ISO text, so Desktop adds no date tables to the certified model.

### Fixed
- P02 Power BI export groups by decision day, so a late inspection record no longer carries the next day's suspension flag (S3 suspended cuts are days 7, 8 and 10).

## [1.6.0] - 2026-11-17

### Added
- Demonstration case P02 (`P02-v1.0.0`, level A, fictitious plant, synthetic operational flow): `quality_ml.pilot_p02` resamples only out-of-fold cross-validation predictions (the 389-plate holdout is never read), reconciles records with seven documented defects checked against synthetic truth, fits `review_policy` cuts on closed reviews only, and assigns daily human review under a hard inspector cap. Three policies are compared (review all, single threshold, prioritized with capacity) in three scenarios, with a capacity, error-cost and calibration sensitivity. It also produces a Power BI export (`seguimiento_revision.csv`) checked against `revision_humana.dax`. Dossier, verdict and self-assessed certificate in `docs/pilots/P02/`; outputs and SHA-256 evidence in `reports/pilots/P02/`, regenerated by CI. Release asset `p02-evidence-<tag>.zip`, built by `deploy/build_release_bundle.sh` and checked by `tests/test_release_p02.py`. The Power BI page itself was not built (reservation R3).
- Certified Power BI Desktop validation (OWNER-PBI-REN-001): the component is renamed to `steel-plates-quality-mlops-powerbi`, the PBIX saved from Desktop 2.156.951.0 (SHA256 `91f89ff2…d86260`) ships through Git LFS — repairing the previous pointer whose object was missing from the server — and the production dossier under `docs/production/` records the live-engine reconciliation with exactly-zero differences against the frozen metrics.

### Changed
- The PBIX is re-saved through Power BI Desktop with `RutaCSV` set to the portable parameter and refreshed against it (issue #2): SHA256 `a37f3743…5bec1`. Same model (7 tables, 34 measures, 3 relationships, 1,941 and 389 rows); the previous certified binary `91f89ff2…` is superseded.
- `RutaCSV` is published as a portable parameter with a neutral single-separator placeholder; the validation machine's local path stays out of version control. The preservation test accepts exactly the historical placeholder and the portable value, pins the Desktop-rewritten report objects byte by byte and checks their semantic core.

### Fixed
- CI: `ubuntu-latest` moved to Ubuntu 26.04, where `actions/python-versions` publishes no Python 3.13.7 build. Jobs that pin 3.13.7 (the Docker base and the interpreter recorded in the artifact manifest) now run on `ubuntu-24.04`.
- `test_previous_powerbi_preserved`: the account rename (`jesusgonzalezmexdata-ux` → `jesusrlgonzalez`, commit fecb642) changed the online data URL in `powerbi/powerquery/00_Parametros.pq`. The test now accepts exactly that owner change and still requires every other byte to match the pre-ML baseline; the baseline hash is unchanged.

## [1.5.0] - 2026-10-17

### Added
- MVP «Triaje de revisión humana» (demo mode «Triaje de revisión»): input template and row-level validation in Spanish; band weights for the reviewed sample; per-class confidence thresholds from a weighted logistic model of P(error); out-of-sample escape estimate with Jeffreys interval; audit sample and alarm; list of parts to review; Power BI export and DAX measures (`powerbi/dax/revision_humana.dax`). Example built from the real plates with out-of-sample predictions (`tools/build_review_example.py`). Pilot protocol in `docs/MVP_PILOTO.md`.
- «Señal de campo» theme and copyright footer in the demo.

### Changed
- This repository absorbs `steel-plates-quality-bi` as its reporting layer; the former repository points here.

## [1.4.0] - 2026-10-16

### Changed
- GitHub Actions updated by the maintainer: `actions/setup-python` v7, `actions/setup-node` v7, `github/codeql-action` v4; `pytest>=9.1.1`.

### Removed
- Dependabot configuration: dependency updates are reviewed and applied manually by the maintainer, so every commit has a single author.

### Added
- Project page on GitHub Pages and a live demo on Hugging Face Spaces, published automatically from `main`.
- Input-drift monitoring (`tools/drift_check.py`, `reports/ml/monitoring/drift.json`): PSI and out-of-range share per measurement against the training plates; the holdout passes, a unit change and a luminosity recalibration are flagged.
- Per-1,000-plates cost of each review policy for illustrative ratios R = 10 and 20 in `review_cost.json`, shown in the README and executive summaries.
- Executive summary in English and Spanish (`docs/EXECUTIVE_SUMMARY.md`, `docs/RESUMEN_EJECUTIVO.md`).
- Assumption-based cost sensitivity of the development-only review policy (`tools/review_cost.py`, `reports/ml/decision/review_cost.json`): break-even ranges of the miss-to-review cost ratio for perfect and imperfect reviewers, checked against brute force. No real costs, savings or new thresholds.

## [1.3.0] - 2026-10-14

### Added
- `steel-predict` command installable with `pip install .`.
- English README as the main entry point; Spanish version in `README.es.md`.
- Packaging tests (entry point, version consistency, license metadata, pinned dependencies).
- Community and governance: `CONTRIBUTING.md` with scientific-integrity rules, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), `SECURITY.md` (pickle risk and private reporting), `CODEOWNERS`.
- Issue forms for bugs, data-quality findings and pre-registered experiment proposals; pull-request checklist that protects the frozen model and the consumed holdout.
- Automation: Dependabot (frozen scientific packages excluded), CodeQL code scanning, label sync, and a release workflow that attaches the verified ONNX model, manifest, Model Card and SHA256SUMS to every published release.

### Changed
- `streamlit` and `plotly` pinned to the versions validated in CI.
- CI runs on pull requests, on `main`, weekly and on demand, with concurrency control and read-only permissions.

### Fixed
- The PBIP `RutaCSV` default no longer contains the author's local path; it ships with a placeholder, and the Power BI preservation test allows only that documented change.

## [1.2.0] - 2026-10-14

### Added
- ONNX export of the frozen model, verified against scikit-learn (max probability difference 8.3e-7, same class and review status) and deterministic by SHA256.
- Node.js batch inference through ONNX Runtime (`examples/onnx-node`).

## [1.1.0] - 2026-10-14

### Added
- Docker image for the Python evidence layer; CI runs the checks and the full suite inside it.
- SQL data contract with dbt + DuckDB (56 checks), reconciled row by row with the Python audit and tested against five corruptions.

## [1.0.0] - 2026-10-14

### Added
- Frozen `tuned_random_forest`, evaluated once on the 389-row holdout: macro-F1 0.8147, balanced accuracy 0.8049, log-loss 0.6893.
- Model Card, evidence pack and clean-clone reproducibility (122 tests).
